# 轨迹验证器优化

此变更只涉及验证器、验证期间的几何缓存及回归测试。不修改 GPT 动作接口、RRTConnect、控制器执行代码或安全配置。

## 结果契约

`verify_joint_box(...)` 返回 JSON 可序列化字典，包含 `status`、`segment`、计数和耗时：

- `SAFE`：原严格区间证明覆盖所有子盒。
- `UNSAFE`：找到盒内具体关节配置，经原 `check_cell_collision` 复核碰撞。`witness` 包含对象名称、`joints_deg`、`gap_mm` 和原因。间隙是含现有位置余量的胶囊间隙，不是实际相机实体穿透深度。
- `UNKNOWN`：节点/时间耗尽或原证明无法得出结论。不能执行。

`certify_joint_box` 和 `validate_native_sweep` 保持原有“返回证书或抛异常”的接口：SAFE 返回证书；UNSAFE 抛 `UnsafeBoxError`，UNKNOWN 抛 `ProofIncompleteError`，异常的 `.result` 保留完整三态结果，错误文本也包含该记录。后者附原轨迹段起终关节角，上层原有指令上下文仍可定位动作。

默认节点上限沿用 `safety.max_sweep_nodes`，显式 `max_nodes` 只能进一步收紧；默认时间上限 120 秒，`verify_joint_box(timeout_s=...)` 可指定，外层候选搜索截止时间优先取更早值。`complete_proof` 现在只提供取消和进度上下文，不再解除预算。一次 FK/几何查询是不可抢占的小计算块，截止时间在计算块之间检查，非硬实时定时器。

## 不改变接受条件的优化

1. 验证期间获取模型可重入锁，建立本次证明独有的精确键缓存。相同姿态跳过重复 URDF FK 更新，复用帧、胶囊、凸包转换、局部位移界、投影区间；半宽、方向和几何参数参与键。缓存最多 512 项，出作用域即销毁，下一次证明重新读取模型与配置。
2. 缓存结果返回独立数组/胶囊副本，调用者不能通过修改返回对象污染后续查询。不缓存碰撞查询结果或 SAFE 判定。
3. 先用不变的区间包络挑选可能接近的相机对，按名义间隙排序。L-BFGS-B 在原关节盒内搜索间隙，最多 96 次目标评估；候选被夹回盒内。任何非正目标值都必须再调用原完整几何碰撞检查器，成功复核才形成 UNSAFE 见证。
4. 搜索未找到见证时，无论优化器是否收敛，都继续原严格证明；原区间二分及全部包络/停止/位置余量保持不变。首个区间包络在搜索和严格证明之间复用，减少安全轨迹的额外成本。

## 离线对比

见 `results/validator_optimization/`：保存修改前的验证器/FK源码、65 个案例、逐案例结果、三次独立运行和统计摘要。`benchmark.py baseline` 加载保存的旧模块，`benchmark.py optimized` 使用当前模块，`benchmark.py cache_only` 关闭快速见证搜索，仅测缓存。没有连接硬件。

65 个案例包含：原相机接近失败段、62 段已保存的可通过真实模型轨迹、2 个已确认不安全状态。原失败案例采用相同 512 节点观察窗口，其他案例采用原配置 4096 节点；这个对比不等于声称旧无限运行最终必然需要多少时间。

三次运行中位数：

| 项目 | 修改前 | 修改后 |
|---|---:|---:|
| 原相机接近失败区间 | 4.763 秒后 UNKNOWN | 0.0341 秒得到 UNSAFE |
| 62 段安全轨迹总耗时 | 0.7350 秒 | 0.6986 秒 |
| 全部 65 案例总耗时 | 5.5249 秒 | 0.7404 秒 |
| 失败区间实际 URDF 更新次数 | 9416 | 34 |
| 62 段安全轨迹 URDF 更新次数 | 1379 | 619 |

缓存单独实验：同一个失败区间仍检查 512 节点、245 个通过子盒、23 个未处理子盒，仍为 UNKNOWN；耗时 1.951 秒，实际 FK 更新 581 次。说明缓存不改变证明覆盖或接受结果，快速反例搜索负责提前发现 UNSAFE。

新版 62 个 SAFE 全保留，2 个原 UNSAFE 全保留，1 个原 UNKNOWN 转为有见证的 UNSAFE。未出现 UNSAFE→SAFE。快速见证的带余量间隙约 −1.15 mm，和此前优化搜索得到的最小值不同：这里找到足以拒绝的第一个复核见证就立即停止，不求最深穿透。

## 测试与限制

回归覆盖：搜索未找到见证仍执行严格证明、负间隙未经原检查器确认不能形成见证、优化器越界候选夹回原盒后复核、UNKNOWN 异常适配、取消、精确姿态/区间缓存、返回值隔离及跨证明配置刷新。

这些性能数据针对保存的案例，不代表所有轨迹都能得到同等加速。未知情况下仍拒绝执行；真正不安全的段需要上层改路，优化不会把它变成安全。
