# 双相机 unfold 观察流程

当前采用的黑衣视觉基线、验证证据与回退方法见
[`vision_baseline_20261106.md`](vision_baseline_20261106.md)。
已启用 `appearance_seam=local_gain`：在缺口附近选择连续拼接线，保护主相机可见布面，
并以统一通道亮度增益减少颜色硬接缝。校正区域保存为 `appearance_color_corrected.npy`。
该基线替代下文历史段落中逐孔直接补图的外观策略；原始实测执行映射仍保留。

`bash scripts/run_arm7_unfold.sh` 默认启用固定 ZED + RealSense。此命令会真实执行既有初始化和 unfold；本次集成只做离线测试，没有启动机器人。

仅检查配置：`bash scripts/run_arm7_unfold.sh --dry-run`。
回到原 ZED 单相机流程：`bash scripts/run_arm7_unfold.sh --single-camera`。

每次观察的流程为：既有静止关节快照 → ZED 原采集逻辑（含时间中值）→ RealSense 原生深度和彩色纹理 → 再次关节快照 → 各自原生光学中心的固定深度比例修正 → world 点云 → 共用 XY 栅格 → 颜色匹配 → planner 主图。初始、reset 后、按压后及每次动作后均重新生成。没有新增运动后端；分区、单臂执行和碰撞路径检查仍由现有运行链负责。

配置为 `config/fusion.unfold_dual.json`，包含当前外参、固定深度比例和颜色回退参数。当前绑定 ZED 11483267、ULTRA HD720，以及 RealSense 254522070945、1280×720 原生深度。移动相机需要更新外参；其他深度模式不能直接沿用这组比例。

每帧在高度接近、颜色平滑的重叠区域拟合 RealSense→ZED RGB 匹配，使用另一组空间块检查颜色误差。样本不足或效果变差时使用已保存的颜色参数，不以颜色拟合失败阻断抓取。颜色处理不改变 XYZ、不补洞。任一相机缺少桌面深度时，可继续使用另一相机的有效点。

主图输出坐标保持为 top-down 像素。执行取点直接使用融合图的实测 `world_xyz_mm.npy`，不再返回单相机做 5×5 / 18 点检查。保留 `source_camera.npy` 和 `source_xy.npy` 进行来源核对及方向转换；两台相机的实测点共同提供局部支持：XY 半径 3 mm、相对所选点 Z 差 5 mm 内至少 3 个不同 XY 观测（0.1 mm 去重），不以重复观测凑数，不填补未知像素，也不把邻域平均成另一个抓点。这些支持条件不等于标定精度保证。记录在 `topdown/depth_resolution.json`。单点孤立或缺少来源时反馈重新选点，不发送运动。reset 后直接重新采集并进入展开；主流程已移除遮挡检测与下压环节。

`--planning-mode pure-oneshot` 与默认 skill 模式使用相同输出 schema、模型调用封装、最多两次深度失败重选、实测距离反馈、坐标映射和执行链；仅规划提示不同。纯 oneshot 不加载 skill 内容，提示直接给抓点和放点。skill 模式在同一次请求中先选择本步最有助于展开的部位，再选择方法：能通过可见抓点直接展开时正常抓放，需要先揭开覆盖层时使用几何技能并给边界定位。Host 复用独立 CV 分割、内法线和正向最远交点生成抓放点，不额外进行语义复核。skill_geometry 保存几何过程和可视化，planning_skills.json 的 action_source 为 measured_cv_candidate；普通抓放为 direct_points。

两种模式首轮发送当前图、目标图；后续增加第三张“上一轮实际执行动作前的俯视图”，供比较动作前后变化，仅保留一轮图像，不发送上一轮动作坐标或指令。所有本轮选点仍使用第一张当前图坐标，深度/距离重选期间不会将未执行候选当作新历史。`planning_context.json` 保存历史来源与哈希，`context_previous_before.png` 保存实际发送的历史图。独立强制技能实验入口不由此改变。

`scripts/compare_unfold_history_offline.py --source <run目录> --goal <目标图> --output <输出目录>`
仅准备和核验成对输入；增加 `--run-model` 才调用现用模型服务。对照组和历史组都使用当前提示词，
历史组只增加上一轮动作前图及其说明，首轮因没有历史而排除。记录模型请求总耗时（包含重选）、
本地规划及离线预检总耗时、抓放点、距离和检查结果，并生成逐轮对照图。每状态每组一次采样，
只能比较已保存状态下的规划，不能当作新轨迹或实机效果验证。

每次观察保存原始点云、修正点云、第二相机原始彩色图及带纹理的原生深度图。`topdown/view.json` 记录颜色拟合/回退、有效点数和源观察 ID。`pixel_mapping.json` 与 `geometry.json` 记录真实动作选点的来源。图像和测量数据仍保留原有哈希校验。

该融合依旧是最高实测表面的投影。颜色一致不代表几何完全一致；第三个板位置的重叠高度绝对差中位数约 5.8 mm，P95 约 19 mm。比例修正来自局部板面验证，不代表全量程或任意衣物的深度精度。

离线衣服观察链示例：`reports/dual_unfold_pipeline_offline_20261105/initial/topdown/planning_rgb.png`。此数据回放仅检查渲染和来源采样；合成测试另行检查来源相机角度变换。未执行物理抓取。

两台相机在选点处均无可用深度时，将具体失败点反馈给同一边界选择模型，最多重新选择两次（总共三次）。每次仍执行相同 CV 和实测检查，不调用候选语义复核，不移动机器人或编造深度。`depth_reselection.json` 记录每次尝试和最终采用的目录；重新选择的资料在 `depth_reselection_01/`、`depth_reselection_02/`。三次仍失败则 ABSTAIN。

## 连续视频

默认运行同时录制 ZED 左目 RGB（1280×720，10 fps，H.264 MP4），保存到
`videos/<run名称>/zed_rgb_32x.mp4`。2026-11-05 检查时，本机唯一可用本地数据盘 `/dev/nvme0n1p2` 剩余约 872 GiB；该目录就在此盘，不使用临时内存盘。
每次 run 的 `video_recording.json` 保存绝对路径、状态和帧数；录像目录另有编码器日志和逐帧时间戳。
这是真实连续视角录像，不是 topdown 重建视频或前后照片幻灯片。

录像从首次机械臂初始化之前开始，覆盖 reset、规划等待和动作，结束时关闭。
相机由一个采集线程持有，原有观察流程获取新鲜 RGB-D 帧并继续做时间中值，不再为观察重复开启同一 ZED。
RealSense 采集保持原流程；当前录像只录 ZED。短暂采集间隔用最新帧维持视频时间轴，时间戳记录重复来源帧。
MP4 使用分片容器以保留异常中断前的片段。编码失败或录制途中空间低于 1 GiB 会停止写录像并记录错误，不改变机械臂动作；启动时无法建立录像则在动作前报错。

关闭录像：`bash scripts/run_arm7_unfold.sh --no-video`。
另选存储根目录：`bash scripts/run_arm7_unfold.sh --video-dir /path/to/videos`。
`--dry-run` 不打开相机、不录像、不驱动机械臂。该功能已用模拟相机和真实编码器离线测试；未为验证录像启动实机实验。

录像结束后自动转成 32 倍速 H.264 MP4，核对时长和分辨率并完整解码验证后，删除原速 `zed_rgb.mp4`。转码或验证失败则保留原片，错误写入录像清单。`video_recording.json` 的 `frames`/`fps` 记录原始采集参数，`playback_speed` 和 `video_duration_s` 说明最终加速视频。

## 独立 CV 轮廓

规划的当前图和目标图是前两张，后续轮次另附上一轮动作前图。Codex 选择三种 skill 之一并给 Q 点（弦线法再给 A/B），不再输出 `visible_polygon_px` 或 `background_points_px`。Host 用浅色低饱和衣物／黄色垫板的颜色先验生成种子，复用 GrabCut 和最大连通区域提取轮廓。轮廓用于既有切线、弦线、法线及最远交点计算。分割只改变掩膜，不补 RGB-D 测量；小型缺测格可在轮廓层桥接，实际抓点仍需原始双相机深度。分割结果与方法记录在每次选点目录的 `mask.png` 和 `segmentation.json`。

此分割针对当前配色；换深色衣物、浅色台面或加入大块同色物体时需重新验证，不能把最大浅色连通块当成通用衣物识别。离线 23 张真实帧的轮廓预览：`reports/independent_cv_segmentation_20261105/comparison.jpg`。旧模型掩膜仅作对照，不是标注真值。


### Skill 切换规则试验（2026-11-07）

默认 `CLOTH_SKILL_SWITCH=layered`：先对照目标选择本步最有助于展开的部位，再选择动作方法。
能通过可见抓点直接展开时使用普通抓放；需要先揭开覆盖层才能展开时使用几何 skill，
并在 `evidence` 中说明要揭开的覆盖层及预期露出的部位。别处存在隐藏衣角或袖口不自动提升 skill 优先级。
覆盖判断依据当前图中的可见叠层关系；普通褶皱、内收或目标形状尚不完整不足以认定遮挡。
如果本步目标是展开袖子，普通动作优先抓取对向的可见袖子向外牵拉，通过摩擦间接展开目标袖子；拉动方向同时要保持衣身主体大致在原处，不能把整件衣服横向拖到桌边或拖离工作区；只有对向袖子本身不可见或不可抓、确实需要先揭开覆盖层时才使用几何 skill。
只有四个外轮廓角都清晰可见、没有角被遮住或卷入，且没有明显大片覆盖或内收时才允许 DONE；任一角不可见、被遮挡、卷入或无法确认，都继续规划动作。选择在现有单次规划请求内完成，不增加受阻检测、失败次数门槛或额外模型调用。
无法可靠定位适用边界或抓放点时 ABSTAIN。最终模型提示只保留一次切换句；几何最远交点和执行链不变。
`planning_skills.json` 记录 `switch_policy`。纯 oneshot 对照不受影响。

拉动幅度提示改为“根据当前折叠状态和目标展开形态选择拉动距离，避免拉过头或过度拉伸衣物”。
skill、pure-oneshot 及距离失败重选均不再引导小步、多轮或额外预留距离余量；实测距离范围、工作空间、深度和碰撞检查保持有效。

恢复原切换提示，无需回滚其他改动：
```bash
CLOTH_SKILL_SWITCH=legacy bash scripts/run_arm7_unfold.sh
```
默认新规则：
```bash
bash scripts/run_arm7_unfold.sh
```
这些命令会启动实机实验。切换仅影响新启动进程；当前自动分割的配色适用性问题不由此修改解决。

## 连续表面 RGB 与黑衣 mask（2026-11-06）

当前 `config/topdown.unfold_zed.json` 设置 `appearance_render: surface_rgb`、
`segmentation_profile: black`。正式规划图 `planning_rgb.png` 现在来自连续表面 RGB：
原生深度邻接三角形（最大边12 mm、Z阶跃10 mm）投影后，从原始彩色图双线性取色，
2倍采样后降采样。不能组成三角面但仍有实测点的格子退回实测点取色。
RealSense 提供主体，ZED 补缺；两路仅使用当前重叠验证通过的乘法增益校色，无黑色抬亮偏移。
当 ZED 观测到主视角之外、具有连续内部支持的更高衣物区域时，保留该上层区域；
紧贴已有轮廓的零碎深度差不触发颜色切换。

封闭颜色空洞最多512个输出像素可做传统颜色补全（不是新测量）。其位置保存在
`appearance_texture_inferred.npy`，显示覆盖保存在 `appearance_valid.npy`。
`appearance_display_z_mm.npy` 仅是显示用插值表面，不能作为抓取深度。
可执行的 `world_xyz_mm.npy` 和 `source_xy.npy` 仍逐点选自原始测量，且与显示表面使用
既有5 mm同表面容差核对；没有合适测量的像素保持未知。原始测量文件不变。
`point_rgb.png` 保留改动前的逐点投影，`rendered_rgb.png` 与规划图一致。

黑衣分割使用渲染图及显示覆盖；从桌面色度分布中区分彩色印花，亮度降低本身不再
成为印花前景证据，减少投影阴影误分。三种技能的法线/最远交点/动作算法未改。
mask 中没有实测深度的格子单独计数，不因颜色补全而放开抓取。

离线对比和复现脚本：`reports/surface_fusion_validation_20261106/`。
8个已保存黑衣状态逐张检查，印花没有再被单独切掉，桌面没有再成为主体mask。
这些是可视核验及回归样例，没有人工逐像素真值，不能据此报告IoU或保证其他配色的精度。
该修改没有启动相机/机器人，没有进行模型规划调用。

回退显示方式：删除 `appearance_render` 字段或设为 `point_rgb`；旧点投影及其来源保持可用。
换衣物配色时应明确修改 `segmentation_profile`，当前黑衣先验不能自动当作通用分割器。
