# 固定观察照片上的实时夹爪 TCP

## 固定 X=420 mm 的扫描实验

本次指定基座坐标 **X=420 mm、Z=50 mm、Y 从 −140 到 +220 mm**。建议先用 10 mm/s，速度必须显式传入，且不能超过机器人配置速度：

```bash
python scripts/live_tcp_overlay.py --real --confirm-real \
  --scan-y -140 220 --scan-z 50 --scan-speed 10
```

1. 初始阶段经 Home 回观察位拍照。这是准备阶段，**还不是固定 X 扫描段**。如果已经在拍照观察位，可加 `--capture-current` 跳过该运动。
2. 照片固定后，使用示教器把 TCP 移到 **(420, −140, 50) mm**，保持希望使用的姿态。确认沿 Y 的路径无遮挡，回到厂商位置控制模式并停止手动运动。
3. 聚焦图像窗口，按 **B**。脚本核对起点、TCP offset、控制器状态和整条轨迹的 IK/工作空间；任一检查失败不会开始运动。当前起点关节用于 IK 验证，不按 Home 假设起点。
4. 只发一条非圆弧混合的笛卡尔直线指令，到 **(420, 220, 50) mm**，保持开始时的 roll/pitch/yaw。扫描段指令的 X 写死为 420，没有随机扰动、往返或自动调整 X 的路线；Z 固定。起步和结束有加减速，中段按设定速度运行，不声称全程瞬间达到恒速。按 10 mm/s 约需 36 秒加上加减速时间。
5. 在终点停住，继续显示反馈。每次拍照只允许一次扫描，失败不会自动重试。按 Esc 或关闭窗口时，如果扫描尚在执行，会请求控制器停止；仍可使用硬件急停。

指令固定 X 不代表物理跟踪误差绝对为零。默认起点 X/Y/Z 容差各 0.5 mm；扫描中实际反馈 `|X−420|>0.5 mm`、Z 误差大于 0.5 mm、Y 越过路径、读数失败/耗时超过 0.5 秒、控制器状态异常或超时，都会请求 `set_state(4)` 停止。`--scan-x-tolerance` 可缩小 X 容差（最大 0.5 mm）。检查不是硬实时控制，检测及停止有延迟，不能保证物理 X 永远不越界。停止后工具不自动复位控制器。

实时记录在 `scan_samples.jsonl`：时间、原始 TCP 位姿、原始 RGB 投影、X/Z 偏差、相邻采样估算的实际 Y 速度。目标采样间隔为 0.05 秒加 SDK 读取耗时，窗口显示 X 偏差和 Y 速度。`scan.json` 保存参数、精确指令、起点、IK 检查、结果、最大实测 X 偏差和停止返回码。`tcp_samples.jsonl` 保留扫描前后读数。图像像素偏置仍只改变显示，不能改变扫描 X/Y/Z。

扫描模式是显式启用的运动实验：即使加了 `--capture-current`，仍要求 `--real --confirm-real`。下面的常规模式在拍照后仍是只读监测。

这个辅助工具先回到观察位并拍照，然后在**固定的原始 RGB 照片**上持续显示机器人反馈的 TCP 位置。适合检查手动移到某个真实标记时，预测像素是否落在那个标记上。

在机器人机器的桌面终端、仓库目录运行：

```bash
python scripts/live_tcp_overlay.py --real --confirm-real
```

1. 工具经 Home 到配置中的 perception 观察位，采集 RGB-D 和相机外参。拍照期间保持机械臂、桌面物体静止。
2. 终端提示 `Reference captured. You may now move manually.` 后，使用示教器或厂商界面自由移动机械臂。工具不自动进入拖动模式；需要手拖时，由你在厂商界面开启支持的示教/拖动模式。
3. 照片固定不变，绿色十字是当前**配置 TCP**在拍照时相机视角下的投影。窗口显示 TCP 基座 XYZ、对应原始像素。
4. 按 `S` 保存当前叠加图和读数，按 Esc 或关闭窗口退出。退出只断开监测连接，不发送回 Home、夹爪或模式切换命令，也不会停止其他控制源的运动。

如果已经停在希望拍照的位置，可跳过所有初始运动：

```bash
python scripts/live_tcp_overlay.py --capture-current
```

可选参数：`--robot-config PATH`、`--perception-config PATH`、`--camera A`、`--output-dir PATH`。需要和手动选点工具相同的 NumPy、Pillow、tkinter、相机 SDK、xArm SDK 和标定依赖。

## 单独尝试显示偏置

为了检验“同一个偏置是否在各处都适用”，只在本工具中增加二维图像偏置。默认 `(0, 0)`，无需猜测偏差毫米数。绿色十字始终是原始 TCP 投影，非零偏置时另画橙色方框并连线。用方向键移动橙色标记，每次 1 个**原始 RGB 像素**，Shift＋方向键每次 10 像素，R 清零。窗口缩放不改变偏置单位；偏置为零时两个点重合，只显示绿色十字。

例如先尝试向图片右边移动 20 像素（示例值，不是标定结果）：

```bash
python scripts/live_tcp_overlay.py --real --confirm-real --pixel-offset 20 0
```

若已经在拍照位置，改用 `--capture-current --pixel-offset 20 0`。公式为 `偏置后像素 = 原始投影像素 + (DU, DV)`，DU 正向右，DV 正向下。这里的方向指窗口所示**原始 RGB**，不是 upright 图或机器人基座方向。

先在一个位置调好，然后保持同一个偏置，把夹爪移到左、中、右及不同高度比较。各处都更接近才说明固定图像偏移在这些观测上有用；不能由此认证外参或直接推导机器人坐标补偿。绿色点偏在实体位置哪一侧，就向相反方向调整橙色点。

此功能仅改变画在照片上的位置，**不会修改 TCP、相机内外参、反馈 XYZ、其他脚本或机器人运动目标**。原始 `tcp_samples.jsonl` 不加偏置。`display_offset.json` 保存最后一次调整值；按 S 的 PNG 含图例，配套 JSON 保存原始读数、当时偏置、原始及偏置后像素。下次启动仍默认零偏置，需要用参数显式复用。读数过期/失败时两种标记都隐藏，偏置后出界也不会强行夹到画面边缘。

## 投影方式与边界

使用拍照时保存的 `K` 和 `X_base_camera`，将当前控制器反馈的 TCP 基座坐标变换到**拍照时的相机坐标系**，再用内参投影。基座 XYZ 从毫米转换为米以匹配外参；腕部移动之后不会重算或替换这张照片的外参。无镜头畸变修正，与当前像素转 XYZ 的针孔模型一致。

绿色点表示 TCP，不代表两片夹指尖端或夹爪轮廓；若 TCP offset 不准确，标记也会偏。投影使用完整三维位置，包括高度：悬停点与其正下方桌面点可能有视差，不做“投到桌面”的高度假设。图上显示位置是几何预测，不检测遮挡，也不代表已经证实标定准确。

监测阶段只读取位姿和当前 TCP offset，不调用使能、模式切换或运动 API。后台约每 0.1 秒读取一次，窗口约每 0.05 秒刷新，不积压旧读数。读数失败、TCP offset 与配置不符或读数超过 1 秒时隐藏标记；点在图外/相机后方也不强行夹到图片边缘。

新建监测连接后，先使用现有机器人接口的初始化检查，最多等待约 1 秒让 SDK 后台 TCP offset 报告更新，避免把初始全零缓存误判为配置改变。等待后仍不匹配则报错；工具不会自动修改控制器 TCP offset 或忽略真实不匹配。

拍照前后读取的 TCP 相差超过 1 mm 或 0.5° 时拒绝建立参考图。这只是静止检查，不能保证逐帧同步，也不能发现拍摄中移动后又回到原位。请等待提示后再移动。

## 保存内容

默认在 run storage 的 `live_tcp_overlay` 辅助目录创建时间戳子目录：

- `rgb.png`、`depth_m.npy`、`camera_A_base_xyz_mm.npy`、`result.json`：参考照片、标定和拍照前后位姿。
- `session.json`：初始模式、固定相机外参、TCP offset、会话状态/错误。
- `tcp_samples.jsonl`：每次读数的时间、延迟、TCP 位姿、投影像素或失败原因。
- `overlay_时间戳.png/json`：按 S 保存的叠加图与对应读数；JSON 中保留过期/失败状态。

建议在桌面左、中、右固定三个可辨识标记，以同一种姿态对准各标记，分别按 S 留图。需要独立核准夹指中心与 TCP 的关系，并考虑悬停高度带来的视差。图上的残差能帮助比较不同位置的偏差，但不能单凭一次投影分离内参、外参、机械臂运动学与 TCP 的误差。
