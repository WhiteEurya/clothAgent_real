# Astra 持续双臂 pipeline

当前动作接口已更新为 **GPT 声明抓点＋持布动作列表，宿主规划前后接近、抓取、释放与回 Home**，详见 [抓点与持布动作接口](codex_grasp_task.md)。下文旧 `move_tcp`/`gripper` 流程仍兼容历史代码；新模型输出遵守上述分工。

```bash
cd /home/sja/clothAgent_real
/home/sja/miniconda3/envs/cali/bin/python scripts/codex_astra_pipeline.py
```

默认执行完整实机循环，使用 `config/dual_arm.local.json`，无需手工准备 scene/state 文件：

1. 读取双臂状态，先打开双侧夹爪并确认完成，通过规划器回 Home，再让相机臂到保存的 perception 关节位姿，到位后采集 RGB-D；保存 RGB、World XYZ 和关节/TCP 状态。
2. 将本轮 obs 和五张顺序参考图交给本机 Codex（`gpt-6-astra`、`high`），只调用一次模型，输出本轮 `motion.py`。不注入历史经验，不另调模型反思或总结。
3. 动作代码输出后，全部动作先规划并验证，通过后交给原生位置执行器，按顺序移动机械臂及操作夹爪。
4. 执行结束进入下一轮，重新经过 Home → perception 采集一次 obs，再规划。不再额外采集 `after` 或生成 `reflection.json`。
5. 同一次规划若从当前 obs 判断已整齐叠好，单独输出 `motion.complete()`，宿主结束循环、不下发动作；`motion.blocked(reason="...")` 也单独输出，但仅跳过本轮，重新观测后继续规划。上一轮结果会传入下一轮提示词。完成声明不能与动作混写，必须基于执行后的下一轮观测。

默认持续迭代直到 `motion.complete()`，可用 `--max-rounds 50` 显式设置轮数上限；模型每次调用默认 900 秒，可用 `--timeout-s` 修改。
也可通过 `--task`、`--config`、`--output` 指定任务、配置和记录位置。`--memory` 仅兼容旧命令，不再读写经验文件。
`scripts/codex_astra_loop.py` 是同一个完整循环的明确入口。
`--single` 保留旧单轮离线代码生成接口；`--read-only`、`--dry-run` 保留只读/预览用途。

## 运动接口

复用昨天 Home 使用的 `PathPlanner`、本地碰撞包络、停止范围证明、速度配置、同帧反馈和位置执行监控。
关节目标先尝试左先/右先；TCP 目标优先按不超过 5 mm/2° 的步长进行单臂 IK，并认证实际位置指令完整关节区间。若直达插值碰撞、证明 UNKNOWN 或中间 IK 失败，则丢弃本条 TCP 指令的整个插值前缀，从原起点到最终 TCP 位姿的 IK 目标调用 OMPL RRTConnect 搜索绕行（120 秒搜索窗口，另一臂保持不动），随后逐段重新认证全部停止范围。只接受精确路径；搜索或最终证明失败均不下发。TCP 目标位姿不变，但绕行不保证沿原笛卡尔直线；终点本身不安全或 IK 无解时仍会失败。日志 `route=tcp_rrtconnect` 和 `direct_failure` 保留切换原因，成功绕行次数记录为 `tcp_rrt_detours`。
细分点用于 IK 和检查，不再全部作为停车点。同一机械臂相邻的移动会尝试合并为一条原生运动，允许跨越相邻 `move_tcp` / `move_joints` 代码语句，因此被合并的途经点不再停车。合并前保留全部原始 IK 节点，将合并关节弦与这些节点的 FK 差异限制在 2 mm/1°，重新认证完整关节区间、工作空间及停止范围；证明失败或 UNKNOWN 则保留已验证短段。不跨夹爪、机械臂切换、关节反向或 Home/观测准备的到位边界。速度、加速度及全部安全余量不变；段数及消除的停车点数 `removed_stops` 记录在 `planning_stats.json`。不使用 SDK 圆角融合：尚未证明其拐角路径与既有区间验证的对应关系。未能合并的拐角或短段之间仍停稳。
验证器采用 SAFE / UNSAFE / UNKNOWN 三态：仅完整严格证明返回 SAFE；快速搜索到的碰撞见证须经原几何检查器复核后返回 UNSAFE，附对象、关节配置、段端点及带余量间隙；预算耗尽返回 UNKNOWN。默认单次验证最多 120 秒，本机 `max_sweep_nodes` 已提高到 65536，候选检查可使用更小预算。保留进度与主动取消；旧调用通过异常适配拒绝 UNSAFE/UNKNOWN，交还原上层重规划，不下发未通过动作。几何缓存只在一次证明内有效，使用精确姿态/区间键，不缓存安全判定。包络、安全余量、停止角范围及执行器均保持原值。详见 `trajectory_validation_optimization.md`。
双臂按顺序执行，不把参考笛卡尔插值宣称为控制器严格直线运动。每次采集前先检查是否已在准备终点；已到位则直接采集，否则执行 Home → perception；模型收到此约定，须先放稳衣物并松开夹爪，宿主在每次实际回 Home 前先打开双侧夹爪并确认完成，未确认则不移动。
观察位姿默认读取 `data/robot/xarm_perception_pose.json`，可在相机配置中用 `perception_pose_file` 指定；按相机序列号、机械臂 IP/轴数/控制箱序列号及 TCP 校验，六轴记录的 SDK 第七轴补位被裁掉。相机臂以外的机械臂停在 Home。每次采集旁的 `before_perception/` 保存动作代码、规划和结果；回位失败不会拍照。
全部动作在首次下发前完成检查；后一个目标不通过时，前面的夹爪动作也不会执行。
Astra 入口不再按观测年龄触发过期：GPT 推理及离线路径验证耗时不会使本轮快照失效。仍检查真实采集标记、标定一致性和下发前关节状态；每轮重新拍照。关节状态检查不能检测衣物被外部移动，因此观测到执行期间需保持现场不被外部改变。其他入口的观测时限保持原行为。

代码坐标仍为 World 米/弧度；观测文件 `world_xyz_mm.npy` 和 `state.json` 明确使用毫米/度，模型必须转换。
本机使用 `astra_grasp_height.mode: per_point_corrected_depth`，每爪使用各自抓点的点云坐标。当前 1° 补偿直接写入 arm6 相机 `mount_from_camera_mm` 的旋转项，平移项及双臂基座保持原值；轴方向由保存的 perception 观测中世界 Y 轴映射到安装坐标系得到。已移除旧的 `world_tilt_correction` 配置，不再绕 arm7 抓点后处理点云。`extrinsic_tilt_correction` 记录原外参、修正外参和参考观测，并随新观测保存；新的标定标识隔离旧经验。这是相机外参的经验倾角补偿，会改变相机看到的两侧抓点 XYZ，不保证 arm7 抓点 Z 完全不变，尚未实机验证。
规划失败即时记录原因。若是未执行任何动作的 IK 失败，下一次模型规划复用当前 obs：完整返回失败报告、原始 GPT 代码、宿主处理后的代码，仅要求修正失败代码及必要相关指令，保留未受失败影响的抓点、折叠顺序和有效动作；真实抓点 IK 失败时允许依据同一保存观测局部调整失败抓点、朝向或双臂分配。修正请求不重发任务规划提示、RGB 或参考图；返回完整的修正代码供宿主验证。报告区分直达插值点 IK 和 RRT 搜索开始前的终点 IK，并记录从 1 开始的指令序号、机械臂、基座目标 mm/deg、seed、近似解误差及接受阈值。其他规划失败仍重新获取 obs；控制器/执行故障停止双臂并结束会话，不自动重新使能重试。

每次代码修正记为新的 `round_NNN` 尝试，继续遵守显式 `--max-rounds` 上限。IK 重试目录的 `before` 链接到原观测，并保存 `observation_reuse.json` 和 `replanning_feedback.json`；不会重复 Home 或拍照，也不产生额外反思调用。成功执行后下一轮恢复新观测。修正代码仍需完整路径验证和下发前实际关节复核。代码修正调用单独计时为 `gpt_code_repair_s`，不是新的任务策略规划。
每轮结果一产生就向终端打印状态和失败原因、失败阶段/指令及记录路径。不生成或打印经验、反思和下一步。`outcome.json` 的 `failure_context` 记录规划指令序号（从 1 开始）、参数及 TCP 插值进度；停止范围验证耗尽节点时，错误包含预算、已检查节点和待检查节点数量。
Ctrl+C/SIGTERM 会停止当前执行。此入口的文件锁避免同时启动两份本循环；不替代其他程序的硬件互斥。

## 简化模型调用

每轮模型输入只有任务、当前 obs、动作接口约定和顺序参考图。没有额外反思调用、历史经验注入或前后图像评审调用。既有经验文件不删除，也不再读取或写入。

## 双臂分工与参考图

模型自主选择单臂或双臂、不同抓点和动作顺序，不强制两爪一起抓；执行器仍按顺序一次移动一臂。允许夹爪闭合后继续尝试折叠，在整轮结束拍照后判断效果，不要求中途持布确认。GPT 根据当前 obs 直接规划。宿主原有路径检查与执行故障停机保持启用。

默认将 `data/reference/fold_states/active/` 中 `state_01` 至 `state_05` 的五张图，按左袖、右袖、左侧衣身、右侧衣身、下摆的折叠顺序，传给每轮唯一一次规划调用。它们是各步完成后的状态示例，GPT 自行判断当前阶段和下一步，程序不另设阶段判断。左右以衣领在上、下摆在下且不镜像的衣物方向为准。参考图并非当前现场，不能照搬像素坐标、尺寸和动作目标。抓点仍依据本轮 RGB-D。

可用 `--reference /path/to/goal.png` 指定参考图，多次指定时按命令行顺序传入，替换默认五张示例。参考图复制到会话 `references/`，`references.json` 记录来源、用途和 SHA-256；经验按任务、标定和参考图内容及顺序隔离，避免更换目标后沿用旧结论。

每轮在 `round_XXX/` 保存 before/after 观测、motion.py、native_plan.json、outcome.json、两次模型调用日志、reflection.json。
会话 `result.json` 的 `MODEL_REPORTED_COMPLETE` 是视觉模型判断，不是独立测量的成功率认证。
当前新增循环做过模拟连接与故障注入回归；尚未完成真实衣服折叠的端到端验证。

## 规划后 Viser 预览

默认启动 `http://127.0.0.1:8088`（`--viser-port` 可更换端口，以终端打印的实际地址为准）。Home/观测准备路径以及每轮动作均在规划完成后先显示，默认验证通过后自动执行，下发前重新检查实际关节是否仍在起点。加 `--manual-execute` 可恢复点击“执行本次已验证规划”后才下发，等待期间保持静止。拒绝的规划不能点击执行，Ctrl+C 取消等待。预览不会额外调用 GPT。

- 绿色标记：两臂起始 TCP；坐标轴及指令序号：各条动作的目标 TCP 位姿。
- 蓝色 arm6 / 橙色 arm7：夹爪 TCP 路径；拖动进度滑条查看双臂 URDF 和 capsule。线条是路径的几何采样，不是控制器执行时间曲线。
- 下拉框区分通过整轮验证的路径与候选路径；失败候选不会冒充可执行路径。
- 选择碰撞记录，红色粗线标出被拒绝段。勾选“显示所选碰撞见证姿态”，双臂切到已复核的误差/停止范围内关节配置，碰撞 capsule 标红并显示对象及带余量间隙。取消勾选可对照名义轨迹。
- UNKNOWN 仅显示黄色未决段，不宣称找到了碰撞。capsule 包含配置几何和位置误差余量；停止/关节误差由具体见证姿态展示，不当作统一加粗半径。

每次规划保存 `trajectory_preview.json`（起始关节、目标、候选段、已验证操作、失败见证及配置快照）。GUI 使用独立 FK 模型，不修改规划器缓存或验证条件。后续 run 不再需要重新推算失败现场。

只读打开已保存的轮次（不会连接机器人）：

  --round results/codex_astra/loop_20261009T080012160754Z/round_001 --port 8089

旧 run 没有完整预览记录时，只显示已保存的路径段、目标和碰撞见证，并标注其配置来自当前本机配置；不伪造缺失路径。独立回放没有执行按钮。pipeline 退出后，其内嵌预览服务也退出，可用上述命令回放。

## 双臂同步更新

Viser 同时加载本轮 `before/rgb.png` 和 `before/world_xyz_mm.npy` 的彩色点云，直接使用已修正的 World 坐标，不重复外参转换。显示最多约 12 万点，可切换可见性及点大小，不修改观测源文件。所选目标用洋红球、光环、姿态轴和坐标标签标记，其余目标按 arm6 蓝色 / arm7 橙色显示小球，点击可选择；标签只显示所选目标，避免密集重叠。准备阶段尚未采集时不借用其他轮次点云。

Viser 新增“当前位置 → 所选目标（示意）”：在“选择目标”中选择动作，半透明 URDF 展示目标关节姿态，进度滑块和“播放姿态转换”展示从本轮观测起点到该目标的关节插值。另一臂保持观测起点；这不是实际规划路径或运动命令。可切回“规划路径 / 碰撞见证”查看原有验证路径和见证。IK 失败时，仅在有有限且符合关节限位的候选解时显示近似模型，并标明 TCP 位置/角度误差；没有可用候选就只显示目标坐标，不伪造成功姿态。目标模型默认只显示所选机械臂，避免叠加整串姿态造成残影。失败规划的执行按钮仍禁用。

离线 IK 已切换为 PyRoki，双臂及 arm7 入口共用。安装、坐标适配和对照测试见 [PyRoki IK](pyroki_ik.md)。原 FK 误差复核、关节限位及路径碰撞证明继续保留。

双臂入口 `scripts/codex_astra_loop.py` 默认自动执行、持续循环并记录每轮与各阶段耗时。首次及后续采集若已在准备终点（arm7 perception、arm6 Home，沿用关节到位容差），直接采集，不操作夹爪、不回 Home。未到位则按原准备流程移动。

当前仅启动 arm7 的 Camera B（233622079809），两臂抓点都来自这台相机的 RGB 和 World 点云。复用 arm7 已校验的 Camera B 外参和 perception 位置，深度曝光 4000 us、增益 16；不继承 Camera A 的倾角修正。双臂均连接并允许参与动作，不加载 arm7-only 的 arm6 固定障碍模式。

同步单臂抓取偏移：每只夹爪闭合前最后一个显式 TCP 目标额外下降 10 mm；接近、抬升、运输和松开目标不变。提示词要求原始观测高度，宿主统一偏移，实际代码与偏移记录保存为 `effective_motion.py` 和 `grasp_height_policy.json`。修改后的目标仍经过原有 IK、路径与碰撞验证。


双臂支持两种输出方式：`motion.grasp(left=...)`、`motion.grasp(right=...)` 或两臂各自抓点的宿主管理模式；也可不用 grasp，显式编排 move_tcp/move_joints/gripper，以支持先后抓取和独立释放。两种模式不在同一轮混用，显式模式结束前由模型放稳并松开衣物。每臂原始抓点仍单独下降 10 mm，不共享另一臂 Z。

双臂入口的数值 IK 每个初值最多 40 次迭代、最多 2 个不同初值；普通单臂入口保留原有预算。重复初值会去重，同一轮完全相同目标和关节初值的成功解可复用，后续路径与碰撞检查照常执行。首次 JIT 编译仍有开销；这不是整个规划流程的墙钟时间上限。验收阈值仍为 0.5 mm / 0.2°，没有因求解加速放宽。

IK 失败通过 outcome.ik_failure 返回机械臂、指令序号、任务阶段、World/基座目标、关节初值、候选解误差、尝试次数、迭代预算、耗时和拒绝原因。代码修正分支将报告及原始代码交回 Codex，复用未执行动作的原观测，不执行失败候选。数值预算内未收敛不会被报告为“已证明不可达”。

关节路径搜索最多尝试两轮；只有一臂移动时只搜索该臂顺序，不重复搜索等价顺序。每次 RRT 搜索预算 30 秒，失败返回 PATH_SEARCH_BUDGET_EXHAUSTED 和碰撞/工作空间原因。拍照准备失败在模型调用前终止 run；这不是 IK 失败。最终路径认证另计，不将搜索预算视为整个规划的硬超时。

同一次 run 的规划和 IK 修正调用使用同一个 Codex 会话，首轮创建，后续以 `session.json` 中的明确 ID 续接。会话 ID 丢失或改变时停止，避免静默丢失上下文。每个新 run 独立创建会话；不再通过 `memory` JSON 摘要交接轮次。


### GPT 每轮规划事件记录

新启动的循环默认开启可观察规划事件记录。GPT 在实际读取、搜索、形成假设、修改候选代码、验证、修正和结束本轮规划时，用中间消息发送带 `PLANNING_TRACE` 标记的简短 JSON；宿主旁路读取事件流，实时追加，不等待最终回答再回忆补写。最终动作格式、只读权限和机器人执行流程保持不变。

- `<run>/planning_trace.jsonl`：跨轮按实际接收顺序追加，`step` 全局递增。
- `<run>/round_NNN/planning_trace.jsonl`：该轮同一组事件。
- `<run>/round_NNN/planner/result.json` 的 `planning_trace`：接收数量、拒收数量、阶段和记录错误；初始化失败另有 `planning_trace_error`。
- `iteration`、`session_id`、`recorded_at`、`model_step`、`source_event_line`、`source_item_id` 用于对应轮次及 `planner/events.jsonl` 中的真实事件。`known` 和 `hypothesis` 是模型显式声明，事实是否正确仍须核对引用的工具/图像证据。

只收集模型主动输出的公共摘要，不从 reasoning 事件、工具输出或最终动作反推出思维过程。`complete` 仅表示收到合法 ORIENT/DONE 边界且无记录错误，不保证每个该记录的事件都被模型报告；`coverage_verified=false` 明确表示未验证完整覆盖。缺失记录不会补造，trace 错误不替代正常任务结果。DONE 只表示本轮规划结束，不表示物理任务完成。额外摘要会增加少量 token 与时间开销，不保证零开销。
